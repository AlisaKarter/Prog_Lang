### Задание 4 **(2)**

*Проверьте работу следующего фрагмента программы на* **Python**.
```
s = 0
for i in range(4):
   for i in range(3):
      s += i
   s += i
print(s)
```
*В результате каких вычислений был получен ответ? Дайте подробный ответ.*

*На основе этих примеров поясните различия между* **С++** и **Python** *при работе с переменными*.

В Python нет блочной области видимости для циклов for. Переменная i во внутреннем цикле — это та же самая переменная, что и во внешнем цикле. Она не создаётся заново, а просто перезаписывается.  
Внешний цикл range(4) — это итератор, который выдаёт значения 0, 1, 2, 3 по очереди. Даже если мы изменим i внутри цикла, на следующей итерации итератор выдаст следующее значение.  

| Итерация внешнего цикла | i в начале (из range(4)) | Внутренний цикл (i = 0, 1, 2) | i после внутреннего цикла | s += i | Значение s |
|:-----------------------:|:--------------------------:|:-------------------------------:|:---------------------------:|:--------:|:------------:|
| 1 | 0 | s += 0+1+2 = 3 | 2 | + 2 | 0 + 3 + 2 = **5** |
| 2 | 1 | s += 0+1+2 = 3 | 2 | + 2 | 5 + 3 + 2 = **10** |
| 3 | 2 | s += 0+1+2 = 3 | 2 | + 2 | 10 + 3 + 2 = **15** |
| 4 | 3 | s += 0+1+2 = 3 | 2 | + 2 | 15 + 3 + 2 = **20** |

В C++ после внутреннего цикла внешняя i сохраняла своё значение (0, 1, 2, 3), поэтому s += i добавляло 0+1+2+3 = 6.  
В Python после внутреннего цикла i всегда равно 2 (последнее значение range(3)), поэтому s += i добавляет 2+2+2+2 = 8.  

Python и C++ по-разному работают с областями видимости переменных в циклах:  
C++ создаёт локальную переменную для каждого цикла — это безопаснее и предсказуемее.  
Python использует одну переменную на всю функцию — это может привести к неожиданным результатам при совпадении имён.

### Задание 8 **(2)**

*Пусть* **a** - *строковая переменная в программе на* **Python**.
*Есть ли разница между работой присваивания*
```b = a```
и
```b = a[:]```
*Напишите программу для демонстрации различий.*

По сути разница есть, но она проявляется только на уровне объектов в памяти, а не в поведении программы.  
b = a — создаёт новую ссылку на тот же объект. Обе переменные указывают на одну и ту же строку в памяти.  
b = a[:] — создаёт новый объект (копию строки). Переменные указывают на разные объекты с одинаковым содержимым.  
Однако, из-за агрессивной оптимизации в современных версиях Python. Интерпретатор настолько умный, что понимает: строки неизменяемы, поэтому нет смысла создавать копию — можно безопасно вернуть тот же объект.  
Чтобы продемонстрировать разницу между b = a (ссылка) и c = a[:] (копия), нужно использовать изменяемый тип данных.

```python
a = 'Hello world'

# Способ 1
b = a
print(f"  a = {a}, id(a) = {id(a)}")
print(f"  b = {b}, id(b) = {id(b)}")
print(f"  a is b: {a is b}")  # True

print()

# Способ 2
c = a[:]
print(f"  a = {a}, id(a) = {id(a)}")
print(f"  c = {c}, id(c) = {id(c)}")
print(f"  a is c: {a is c}")  # True

print()

# Значения равны
print(f"a == b: {a == b}")  
print(f"a == c: {a == c}")  
```

*Пусть* **a**, **b**  *два списка в* **Python**. *Мы хотим обменять значения переменных следующим
образом.*
```
a, b = b, a
```
*Будет ли это работать? В какой последовательности будут происходить присваивания?
Будет ли зависеть время работы от размера списков? Обоснуйте ответ.*

Да, это работает корректно. Значения списков полностью меняются местами.  
Python выполняет эту операцию в два этапа:

1. Вычисление правой части. Сначала Python вычисляет всё, что стоит справа от =, и создаёт кортеж из ссылок.
2. Затем Python распаковывает кортеж в переменные слева

Оба присваивания происходят одновременно, поэтому не возникает ситуации, когда одна переменная уже изменена, а другая ещё нет.  
Время работы не зависит от размера списков.  
В Python переменные — это ссылки на объекты в памяти, а не сами объекты. Операция a, b = b, a:  
Не копирует содержимое списков  
Не создаёт новые списки  
Просто меняет местами ссылки в переменных a и b  
Обмен двух ссылок занимает константное время, то есть время не зависит от того, содержат ли списки 2 элемента или 2 миллиона.
