## Задание 1 (2)

Оцените работу следующих фрагментов программ. Какие из них обладают неоднозначным поведением? Почему?

### Фрагмент 1:
```cpp
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```

**Неоднозначное поведение (UB).** В вызове функции `std::min(x=15, x+y)` происходит одновременное изменение переменной `x` (через `x=15`) и её чтение (через `x+y`) без точки следования между ними. Стандарт C++ не определяет порядок вычисления аргументов функции, поэтому результат непредсказуем.

Возможные исходы:
- Если сначала вычислится `x=15`, потом `x+y` → `std::min(15, 18) = 15`
- Если сначала вычислится `x+y` (со старым x=10), потом `x=15` → `std::min(15, 13) = 13`

### Фрагмент 2:
```cpp
int x=10, y=3;
x=15, y+=x, x+=y;
```

**Определённое поведение.** Оператор запятая `,` является точкой следования — все побочные эффекты левого операнда завершаются до вычисления правого. Вычисление идёт слева направо:

1. `x=15` → x становится 15
2. `y+=x` → y = 3 + 15 = 18
3. `x+=y` → x = 15 + 18 = 33

Результат: `x=33, y=18`

### Фрагмент 3:
```cpp
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;
cout << y;
```

**Определённое поведение.** Оператор `&&` (логическое И) является точкой следования — левый операнд полностью вычисляется до правого. Кроме того, работает ленивое вычисление: если левый операнд ложен, правый не вычисляется.

1. `x > y++` → `10 > 9` → `true`, после этого `y` становится 10
2. Так как левая часть истинна, вычисляется правая: `y++ > 9` → `10 > 9` → `true`, после этого `y` становится 11
3. Оба условия истинны → выводится "yes"
4. Выводится `y` = **11**

## Задание 2 (2)

Как записать следующие строки программы на С++ в виде одного выражения? Приведите несколько способов, в том числе с использованием операторов инкремента.

```cpp
x=x+1;
z=z+2*x+3*y;
y=y+1;
```

### Способ 1: С использованием постфиксных инкрементов
```cpp
z = z + 2*(x+1) + 3*y, y++, x++;
```
Здесь важно, что `x+1` вычисляется до инкремента `x++`.

### Способ 2: С использованием префиксных инкрементов
```cpp
z = z + 2*(++x) + 3*y, ++y;
```
`++x` увеличивает x до использования в выражении, `++y` выполняется после (через оператор запятая).

### Способ 3: Через оператор запятая
```cpp
++x, z = z + 2*x + 3*y, ++y;
```
Оператор запятая гарантирует последовательное выполнение: сначала `++x`, потом вычисление `z`, потом `++y`.

### Способ 4: Комбинированный
```cpp
z += 2*(++x) + 3*(y++);
```
Здесь `++x` увеличивает x до использования, а `y++` использует старое значение y (как в исходном коде, где `y` ещё не увеличена при вычислении z).

## Задание 3 (2)

Рассмотрите следующий фрагмент программы. Он заполняет вектор из 10 элементов единицами.

```cpp
std::vector<int> x(10);
for (int i = 0; i < 10;)
   x[i++] = 1;
```

Здесь `i++` — постфиксный инкремент: сначала используется текущее значение `i` как индекс, потом `i` увеличивается.

### Переписанный вариант с префиксным инкрементом:

```cpp
std::vector<int> x(10);
for (int i = -1; i < 9;)
    x[++i] = 1;
```

**Объяснение:**
- Начальное значение `i = -1` (вместо 0)
- Условие `i < 9` (вместо `i < 10`)
- `++i` — префиксный инкремент: сначала `i` увеличивается, потом используется как индекс

Таблица выполнения:

| Итерация | `i` до `++i` | `i` после `++i` | Индекс |
|----------|--------------|-----------------|--------|
| 1 | -1 | 0 | x[0] = 1 |
| 2 | 0 | 1 | x[1] = 1 |
| ... | ... | ... | ... |
| 10 | 8 | 9 | x[9] = 1 |

Результат идентичен исходному — все 10 элементов заполнены единицами.

## Задание 4 (2)

Почему присваивание `(++x)=y` является синтаксически правильным, а `(x++)=y` - нет?

**`++x` (префиксный инкремент)** возвращает **lvalue** — ссылку на саму переменную `x` после увеличения. Поскольку это lvalue, ему можно присвоить значение:

```cpp
int x = 5, y = 10;
(++x) = y;  // x становится 6, потом ему присваивается 10
// Результат: x = 10
```

**`x++` (постфиксный инкремент)** возвращает **prvalue** (временное значение) — копию старого значения `x` до увеличения. Временному значению нельзя присвоить что-либо, так как оно не имеет адреса в памяти:

```cpp
int x = 5, y = 10;
(x++) = y;  // ОШИБКА КОМПИЛЯЦИИ
```

### Сообщение об ошибке (g++):
```
error: lvalue required as left operand of assignment
```

**Перевод:** "требуется lvalue в качестве левого операнда присваивания"

**Объяснение:** Оператор `=` требует, чтобы слева стояло lvalue — выражение, обозначающее объект в памяти, которому можно присвоить значение. `x++` возвращает временное значение (prvalue), которое не является lvalue, поэтому присваивание невозможно.

## Задание 5 (2)

Программисты на Python для обмена значений двух переменных часто пишут строку `a,b = b,a`. Проверьте, будет ли аналогичная строка на С++ (с точкой с запятой в конце) являться синтаксически правильной? Будет ли она обменивать значения переменных? Как в языке С++ вычисляется это выражение?

В C++ эта строка **не является синтаксически правильной** в том виде, в котором она работает в Python.

Если написать `a, b = b, a;` в C++, компилятор воспримет это как:
- `a` — выражение (просто переменная, результат игнорируется)
- `b = b` — присваивание (b присваивается само себе)
- `, a` — ещё одно выражение через оператор запятая

То есть это **не обмен значениями**, а бессмысленный код.

### Как работает выражение `a, b = b, a` в C++?

Оператор запятая в C++ вычисляет операнды слева направо и возвращает значение последнего. Выражение разбирается так:

```
(a), (b = b), (a)
```

1. Вычисляется `a` (результат игнорируется)
2. Вычисляется `b = b` (b присваивается само себе)
3. Вычисляется `a` (результат — значение выражения)

**Никакого обмена не происходит.**

### Правильный обмен в C++:

```cpp
// Способ 1: std::swap
std::swap(a, b);

// Способ 2: через временную переменную
int temp = a;
a = b;
b = temp;

// Способ 3: арифметический (только для чисел)
a = a + b;
b = a - b;
a = a - b;
```

## Задание 6 (2)

Проверьте работу следующего фрагмента программы:

```cpp
std::string s;
for (int i=0; i<1000000; i++)
   s += 'a';
std::cout << s.size();
```

Вывод: `1000000`

### Изменённый код:
```cpp
std::string s;
for (int i=0; i<1000000; i++)
   s = s + 'a';
std::cout << s.size();
```

Вывод: тоже `1000000`, **но работает гораздо медленнее**.

### Объяснение

**`s += 'a'`** — добавляет символ **к существующей строке**. Если в строке есть запас ёмкости (capacity), символ просто дописывается в конец без выделения новой памяти. Даже если capacity исчерпан, выделяется новый буфер, и данные **перемещаются** (move) один раз.

**`s = s + 'a'`** — создаёт **новый временный объект** `std::string` на каждой итерации:
1. Вычисляется `s + 'a'` → создаётся новая строка (копируется вся старая строка + добавляется символ)
2. Результат присваивается обратно в `s`
3. Временный объект уничтожается

На i-й итерации копируется **i символов**. Итого: 1 + 2 + 3 + ... + 1000000 ≈ **500 миллиардов операций копирования**.

### Вывод

Результат одинаковый (`1000000`), но `s = s + 'a'` работает **на порядки медленнее** из-за создания временных объектов и многократного копирования данных.

## Задание 7 (2)

Как работает следующая программа? Как зависит результат от исходного значения?

```cpp
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```

### Как это работает?

Выражение `x-->0` — это не специальный оператор, а **комбинация постфиксного декремента `x--` и оператора `>0`**. То есть `x-->0` равносильно `(x--) > 0`.

Оператор `&&` (логическое И):
- Вычисляется **слева направо**
- Является **точкой следования**
- Работает **лениво**: если левый операнд ложен, правый не вычисляется

### Примеры:

**Ввод: x = 5**
- `5>0` (true), x=4
- `4>0` (true), x=3
- `3>0` (true), x=2
- `2>0` (true), x=1
- `1>0` (true), x=0
- Вывод: **0**

**Ввод: x = 3**
- `3>0` (true), x=2
- `2>0` (true), x=1
- `1>0` (true), x=0
- `0>0` (false) → ленивое вычисление, последнее `x--` не выполняется
- Вывод: **0**

**Ввод: x = 0**
- `0>0` (false) → все остальные не вычисляются
- Вывод: **0**

**Ввод: x = -1**
- `-1>0` (false) → все остальные не вычисляются
- Вывод: **-1**

### Зависимость от исходного значения:

| Исходное x | Сколько раз выполнится `x--` | Результат |
|------------|------------------------------|-----------|
| x ≤ 0 | 0 раз | x не меняется |
| x = 1 | 1 раз | 0 |
| x = 2 | 2 раза | 0 |
| x = 3 | 3 раза | 0 |
| x = 4 | 4 раза | 0 |
| x ≥ 5 | 5 раз | x-5 |

Программа **уменьшает x на 1 до 5 раз**, пока x не станет ≤ 0 или не будет выполнено 5 декрементов.

## Задание 8 (3)

Какое число выводит следующий фрагмент программы? Посчитайте результат без использования вычислительной техники.

```cpp
int s = 0;
for (int i = 0, j = 5;i+j <= 16;(i<j ? i : j)++)
   (s += i) += j;
std::cout << s;
```

### Пошаговое выполнение:

**Начало:** `s=0, i=0, j=5`, проверка `0+5=5 <= 16` → true

| Итерация | i | j | i+j | Условие | (s+=i)+=j | s после | Инкремент (i<j?i:j)++ |
|----------|---|---|-----|---------|-----------|---------|----------------------|
| 1 | 0 | 5 | 5 | ✓ | (0+0)+5=5 | 5 | i<j → i++ → i=1 |
| 2 | 1 | 5 | 6 | ✓ | (5+1)+5=11 | 11 | i<j → i++ → i=2 |
| 3 | 2 | 5 | 7 | ✓ | (11+2)+5=18 | 18 | i<j → i++ → i=3 |
| 4 | 3 | 5 | 8 | ✓ | (18+3)+5=26 | 26 | i<j → i++ → i=4 |
| 5 | 4 | 5 | 9 | ✓ | (26+4)+5=35 | 35 | i<j → i++ → i=5 |
| 6 | 5 | 5 | 10 | ✓ | (35+5)+5=45 | 45 | i==j → j++ → j=6 |
| 7 | 5 | 6 | 11 | ✓ | (45+5)+6=56 | 56 | i<j → i++ → i=6 |
| 8 | 6 | 6 | 12 | ✓ | (56+6)+6=68 | 68 | i==j → j++ → j=7 |
| 9 | 6 | 7 | 13 | ✓ | (68+6)+7=81 | 81 | i<j → i++ → i=7 |
| 10 | 7 | 7 | 14 | ✓ | (81+7)+7=95 | 95 | i==j → j++ → j=8 |
| 11 | 7 | 8 | 15 | ✓ | (95+7)+8=110 | 110 | i<j → i++ → i=8 |
| 12 | 8 | 8 | 16 | ✓ | (110+8)+8=126 | 126 | i==j → j++ → j=9 |
| 13 | 8 | 9 | 17 | ✗ | — | — | — |

**Ответ: 126**

### Ключевые моменты:
- `(s += i) += j` — сначала к s прибавляется i, потом к результату прибавляется j. Итого `s = s + i + j`.
- `(i<j ? i : j)++` — увеличивается та переменная, которая меньше (или j при равенстве).

## Задание 9 (3)

Рассмотрите следующую программу. Предполагается, что на вход подается некоторый индекс в массиве - число от нуля до девяти и значение, которое надо записать по этому индексу.

```cpp
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];
std::cout << x[i];
```

### Проблема

В выражении `std::cin >> i >> x[i]` **порядок вычисления операндов не определён стандартом C++** (до C++17). Компилятор может:
1. Сначала прочитать `i`, потом вычислить `x[i]` — тогда используется введённое значение i
2. Сначала вычислить `x[i]` (с i=0), потом прочитать i — тогда запись идёт в x[0]

### Разные компиляторы:

**g++ (GCC) до C++17:**
- Ввод: `5 42`
- Может сначала вычислить `x[0]` (так как i ещё = 0), записать 42 в x[0]
- Вывод: `x[5]` = **0** (неинициализированный элемент)

**clang++ или MSVC:**
- Ввод: `5 42`
- Сначала читает i=5, потом вычисляет x[5]
- Вывод: **42**

### В C++17 и новее

Начиная с C++17, для оператора `>>` введён **строгий порядок вычисления слева направо**. Поэтому `std::cin >> i >> x[i]` гарантированно сначала читает i, потом использует его для индексации. Программа будет работать корректно на всех компиляторах.

### Как исправить для старых стандартов:

```cpp
std::cin >> i;
std::cin >> x[i];
std::cout << x[i];
```

Разделение на два оператора гарантирует точку следования между чтением i и использованием его как индекса.
