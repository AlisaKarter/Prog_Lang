### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)

```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

Функция int() отбрасывает дробную часть, а не округляет до ближайшего целого  

Исправленный вариант:
```

```
Функция round() округляет до ближайшего целого, компенсируя малые погрешности

### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?
```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```
Минимальное значение n для double = 1024  
Минимальное значение n для long double = 16384  
Функция pow(2, n) вычисляет 2^n  
Поскольку 2^1024 не помещается в диапазон double, происходит переполнение, и результат становится inf (бесконечность).
Переполнение происходит, когда результат вычисления превышает максимальное значение, которое может хранить тип данных. Для double это 2^1024, для long double это 2^16384. Разница из-за разного количества бит выделенных для типов.

### Задание 8 **(2)**

*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

Тип double может точно представлять все целые числа до 2^53 (9 007 199 254 740 992).  
Начиная с 2^53 + 1, некоторые числа теряют точность из-за ограничения в 53 значащих бита.  
Число 9007199254740993 при нормализации: 1.0000000000000000000000000000000000000000000000000001 * 2^53  
После запятой должно быть 52 бита, но у нас 53 бита (52 нуля + 1). Последний бит не помещается в мантиссу и отбрасывается при округлении.  
Результат: число округляется до 9007199254740992  
Но чётные числа после 2^53 всё ещё могут представляться точно, так как их двоичное представление требует меньше значащих бит.  
Число 9007199254740994 при нормализации: 1.0000000000000000000000000000000000000000000000000010 * 2^53  
После запятой ровно 52 бита
